## 2024-07-04 - Dangerous Line Manipulations with Sed
**Learning:** Hardcoded line number deletions with consecutive `sed -i` commands (e.g., `sed -i '296d'`) without recalculating line numbers after each deletion shifts the remaining lines and causes destructive data loss (like deleting valid arrays and entries in `data.ts`). Additionally, running package manager commands like `pnpm install` just to get lint commands working can unintentionally generate `pnpm-lock.yaml` files, which must be cleaned up if they're not part of the scope.
**Action:** Always prefer `replace_with_git_merge_diff` over `sed` for complex or multi-line removals, such as fixing Git merge conflict markers. If `sed` must be used for multi-line deletion, use ranges (`sed -i '295,297d'`) instead of individual line deletions, and always verify the result immediately with `sed -n` before proceeding. When checking local state, always unstage and remove unintended artifacts like lockfiles.
