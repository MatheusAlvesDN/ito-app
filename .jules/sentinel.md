## 2025-03-01 - Infinite Loop DoS in Player Assignment
**Vulnerability:** The application allowed an unlimited number of players to be added in `App.tsx`. However, the random number assignment logic in `GameScreen.tsx` used a bounded `do...while` loop constrained to 100 choices (`Math.random() * 100 + 1`). If a user added 100 or more players, the `do...while` loop would run infinitely, causing a Denial of Service (DoS) and memory exhaustion on the client side.
**Learning:** Bounded randomized pools (like a pool of 100 choices) must always be paired with corresponding limits on the inputs that consume from those pools. The lack of a player limit exposed the application to an algorithmic infinite loop trap.
**Prevention:** Always enforce strict validation and limit the size of input arrays when they are later used to exhaust a finite pool of choices. In this case, capping the number of players at 20 (well below 100) and limiting name length (to prevent large payloads) mitigates the risk.
