## 2025-04-08 - Infinite Loop DoS from Unbounded Input Array
**Vulnerability:** The application allowed an unlimited number of players to be added via the UI. During the game phase, a `do...while` loop assigned unique random numbers between 1 and 100 to each player. If the number of players approached or exceeded 100, the rejection sampling loop would become an infinite loop or cause severe memory exhaustion/CPU spiking, resulting in a Denial of Service (DoS) for the client application. Furthermore, the name input field lacked a length limit, posing an additional memory exhaustion vector.
**Learning:** Bounded randomized pools (e.g., assigning unique values from a fixed-size set like 1-100) must have structurally enforced input limits. If the requested number of unique assignments can exceed the pool size, rejection sampling mechanisms (like `do...while` sets) will inevitably fail or lock up the thread.
**Prevention:** Always enforce structural limits on input arrays (e.g., `localPlayers.length < 20`) when those arrays dictate the number of iterations in bounded generation loops. Additionally, always apply strict string length bounds (`maxLength={30}`) to text inputs handling unbounded user data.
