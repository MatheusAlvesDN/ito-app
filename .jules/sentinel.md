## 2024-03-22 - DoS risks and insecure random generation
**Vulnerability:** Found two vulnerabilities. The first is a potential DoS vulnerability where the number of players was uncapped, possibly creating infinite loops later in the game's secret allocation sequence if greater than 100. Furthermore, there was no `maxLength` constraint on player names input. The second vulnerability was insecure random assignment of secrets using `Math.random()`.
**Learning:** React state arrays are vulnerable to DoS (memory exhaustion or application crashes) if populated by unbounded text inputs. In addition, using `Math.random()` for assigning secrets is highly discouraged as it is insecure and predictable.
**Prevention:** Always enforce `maxLength` on text inputs and validate length before state updates. The number of maximum array elements should be capped to prevent exhaustion and loop errors. Use `crypto.getRandomValues()` directly (or via wrappers like `getSecureRandomInt`) for logical random assignments instead of `Math.random()`.
