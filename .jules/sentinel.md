## 2024-03-24 - Unbounded Input Interacting with Bounded Randomization Loop
**Vulnerability:** A Denial of Service (DoS) and potential memory exhaustion risk existed in the game loop. The `GameScreen.tsx` component assigns a unique random number (from 1 to 100) to each player using a `do...while` loop and a `Set` to track used numbers. However, `App.tsx` did not restrict the number of players that could be registered.
**Learning:** If a user registers more than 100 players, the `do...while` loop in `GameScreen.tsx` will enter an infinite loop, as it attempts to find a unique number between 1 and 100 when all 100 numbers have already been used. This crashes the browser tab. Additionally, extremely long player names could cause performance degradation or memory issues in the UI rendering. This demonstrates how a vulnerability can arise from the interaction between unbounded input in one component (registration) and bounded logic in another (number generation).
**Prevention:** Always enforce upper bounds on user inputs (e.g., maximum array lengths, maximum string lengths) at the point of entry, especially when those inputs dictate the number of iterations in downstream logic. Verify that the maximum input size is safely within the bounds of any hardcoded limits in the application logic.
