## 2024-05-24 - DoS vulnerability in bounded random assignment loops
**Vulnerability:** The application allowed an unlimited number of players to be added to the game. This unbounded input, combined with a `do...while` loop that selected a unique random number between 1 and 100 for each player, led to an infinite loop Denial of Service (DoS) and potential memory exhaustion condition if the number of players exceeded 100.
**Learning:** Bounded loops that assign unique values from a limited pool (e.g., 1 to 100) are susceptible to infinite loops if the number of requests (e.g., players) is not strictly capped to be significantly smaller than the available pool.
**Prevention:** Always enforce a strict maximum limit on the input array size (e.g., a maximum of 20 players) and bound the lengths of inputs (e.g., player names) when using `do...while` loops for randomized selection from a finite pool to prevent infinite loop DoS conditions. Use cryptographically secure assignment methods like `getSecureRandomInt` where appropriate.
