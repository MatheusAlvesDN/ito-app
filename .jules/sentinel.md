## 2024-04-28 - Unbounded Array to Bounded Pool DoS
**Vulnerability:** The application allowed an unlimited number of players to be added and their names to be of unbounded length. These unbounded arrays were then fed into a bounded randomization pool (`Math.floor(Math.random() * 100) + 1` in `GameScreen.tsx` with a `do...while` uniqueness check). If the number of players reached or exceeded 100, the application would enter an infinite loop, causing memory exhaustion and a Denial of Service (DoS).
**Learning:** Bounded uniqueness checks (like `do...while` loops picking random unique numbers from a limited set) require the input array size to be strictly capped to be significantly smaller than the available pool to prevent infinite loop DoS conditions. Unbounded arrays mapping to finite constrained resources is a critical architectural risk.
**Prevention:** Always enforce strict hard limits on user input counts (`localPlayers.length < 20`) and input lengths (`maxLength={30}`) at the UI level. Never allow dynamically growing arrays to be used as iteration conditions against finite pools without proper boundary validation.
