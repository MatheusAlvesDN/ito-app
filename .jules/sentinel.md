## 2025-03-01 - Infinite Loop DoS from Bounded Random Allocation
**Vulnerability:** A Denial of Service (DoS) vulnerability existed in `GameScreen.tsx` where unique random numbers between 1 and 100 were assigned to players using a `do...while` loop. If the number of players reached or exceeded 100 (which was possible as there was no client-side limit in `App.tsx`), the application would enter an infinite loop trying to find an unused number, causing the browser to freeze and crash. Additionally, `Math.random()` was used for these assignments, which is not cryptographically secure.
**Learning:** Bounded random selection loops (e.g., picking unique items from a set of size N) must inherently trust that the number of requested items (M) is strictly less than or equal to N (M <= N), or ideally much smaller to avoid severe performance degradation. This codebase lacked the necessary M <= N constraint on the frontend.
**Prevention:** Always pair bounded retry logic (like `do...while` on sets) with strict input validation that enforces the upper limit. In this app, a maximum of 20 players was enforced in `App.tsx`. Furthermore, security-critical random logic should use the provided `getSecureRandomInt` utility instead of `Math.random()`.
