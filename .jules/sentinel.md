## 2024-05-30 - DoS via Infinite Loop in Bounded Random Choice Generation
**Vulnerability:** The random number assignment logic in `GameScreen.tsx` used a `do...while` loop to find a unique random number between 1 and 100 for each player. However, the number of players was not bounded. If a user added more than 100 players, the set of available unique numbers would be exhausted, resulting in an infinite loop that would crash the application (Denial of Service). Additionally, player names lacked length limits.
**Learning:** Finite sets of resources (like a small pool of random numbers) must always be paired with hard bounds on the number of consumers. Missing input validation (number of players, length of names) directly translated into an algorithmic complexity vulnerability.
**Prevention:** Enforce maximum limits on dynamic arrays (e.g., max 20 players) and maximum lengths on user inputs (e.g., `maxLength={30}`) at the point of data entry, especially when that data dictates the size of loops or resource allocation later in the application.
