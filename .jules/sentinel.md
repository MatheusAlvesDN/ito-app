## 2024-03-20 - Unbounded Collection DoS in Random Assignment
**Vulnerability:** The application allowed adding an unlimited number of players (unbounded array) which were then passed to a `do...while` loop in `GameScreen.tsx` that randomly generated distinct numbers between 1 and 100 for each player. If more than 100 players were added, the loop would run infinitely, causing denial of service and memory exhaustion.
**Learning:** Any logic that guarantees uniqueness from a finite set (like numbers 1-100) using a `do...while` rejection loop is inherently vulnerable to infinite loops if the input size can exceed or approach the set size. Unbounded inputs combined with O(N) or unbounded generation algorithms create severe DoS risks.
**Prevention:** Always enforce strict upper bounds on user-generated collections (e.g., maximum number of players) early in the input phase. Additionally, validate input lengths (e.g., player names) to prevent memory exhaustion, and consider using safe random selection algorithms (like Fisher-Yates shuffle on an array of 1-100) instead of unbounded rejection loops when selecting many unique items from a small set.
