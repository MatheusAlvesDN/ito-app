## 2024-05-11 - Infinite Loop DoS from Unbounded Input
**Vulnerability:** The application allowed an unlimited number of players to be added. In the game screen, a random number from 1 to 100 is assigned to each player, ensuring no duplicates via a `do...while` loop and a `Set`. If more than 100 players were added, the `do...while` loop would run infinitely, causing a Denial of Service (DoS) and crashing the browser.
**Learning:** Bounded algorithmic constraints (like generating exactly 100 unique random numbers) must be strictly mirrored by frontend input validation limits. Failing to enforce limits on unbounded user input can directly lead to logic failures and resource exhaustion.
**Prevention:** Always implement explicit upper bounds on arrays and user-generated lists, especially when their size dictates the number of iterations in a backend or critical frontend algorithm. Additionally, add reasonable length constraints on string inputs (`maxLength`) to prevent memory exhaustion.
